# Contributing

1. Keep the core generic and site-agnostic.
2. Add tests for parsing, audit rules, and safety checks.
3. Do not add real domains, analytics IDs, API keys, customer data, or copied production content.
4. Keep automation proposal-only unless a separate, explicit opt-in is added.
5. Run `npm run check` before opening a pull request.

Pull requests should explain the operational risk, the human approval point, and how a site owner can roll the change back.
